# @repo/db

Shared Prisma client for the monorepo. Apps import models/types via `@repo/db`
(re-exported from `./generated/prisma/client`, generated by the `prisma-client`
generator — not the legacy `prisma-client-js`).

## Scripts

- `npm run generate` — regenerate the Prisma Client (`prisma generate`)
- `npm run migrate:dev` — create/apply a migration (`prisma migrate dev`)
- `npm run studio` — open Prisma Studio

## Known issue: pinned `prisma` / `@prisma/client` version (do not `npm audit fix`)

`prisma` and `@prisma/client` are intentionally pinned to matched `6.18.0`.
`npm audit` reports 4 high-severity findings at this version
(`deepmerge-ts`/`effect`, pulled in via `@prisma/config`'s CLI-side config
merging — GHSA-ggr8-5vv4-36mx, GHSA-38f7-945m-qr2g). **Do not run
`npm audit fix` or `npm audit fix --force` on this package** — both were
tried and neither works:

- Plain `npm audit fix` only bumps the top-level `prisma` devDependency
  (e.g. to `^6.12.0`), leaving `@prisma/client` at `6.18.0`. This mismatches
  the two packages (they must stay in lockstep) **and** doesn't even clear
  the advisory, since `@prisma/client@6.18.0` still pulls its own nested
  `prisma@6.18.0` internally.
- `npm audit fix --force` (downgrading both to matched `6.12.0`) does clear
  the advisory, but `6.12.0` has a real bug loading this project's
  `prisma.config.ts`: `TypeError: (0, _config2.env) is not a function`
  when importing `env` from `prisma/config`. There is no `6.12.x` patch
  release to fall back to — `6.12.0` is the only stable release in that
  line; the next one, `6.13.0`, is back inside the vulnerable range.

**Exposure is low in the meantime:** the vulnerable code path runs when
*you* invoke the Prisma CLI locally (`generate`/`migrate`), not inside the
deployed app's request path — it's not reachable by anything the running
app talks to.

**Revisit when:** a future `prisma` release both clears the advisory and
fixes the `prisma.config.ts` config-loader bug — check `npm audit` again
next time there's a reason to upgrade Prisma anyway, rather than chasing
this in isolation.
